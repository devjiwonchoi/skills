# Multi-agent debate

1. Before final authorization, give separate agents the same current candidate and alignment for independent reviews.
   - **Advocate:** Defend useful choices and explain benefits and tradeoffs.
   - **Critic:** Find failure scenarios, unnecessary complexity, and better alternatives.
   - **Skeptic:** Challenge assumptions and unsupported claims.
2. Share the reviews, have reviewers rebut one another, and identify supported corrections. Resolve supported findings and bring consequential unresolved decisions to the user.
3. Group candidate changes into a new version and re-review affected behavior before final acceptance or approval through [Plan](../SKILL.md). Return intention changes to [Align](../../align/SKILL.md) before dependent work.
4. Require every reviewer to explicitly approve the same current content and version with no substantive blocker unresolved. Reviewer consensus does not supply user authorization.
5. Repeat within a bounded round budget. Stop when the budget is exhausted or discussion makes no progress. Return the current plan with unresolved objections and needed evidence or user decisions.
   - If separate agents are unavailable, report that multi-agent consensus is incomplete.
