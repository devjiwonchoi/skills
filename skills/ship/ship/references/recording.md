# Delivery recording

Use the shared [CLI setup](../../../utils/references/recording.md) and the same task/session as Iterate. Ship records `.jwn/<session-id>/ship/v1.jsonl` through `ship <read|write|next>`. Inspect `ship --schema` for fields. Ship does not authorize execution, merge, deploy, reviewer requests or messages.

1. Initialize `start` once with the goal and the actual authorization source. Reuse Plan permissions without inventing or broadening them.
2. Before commit, push, PR creation/update or CI rerun, record `attempt` with its target and expected remote head. Perform only that authorized operation and record `result` with actual output files. An unmatched or `uncertain` attempt requires inspecting local/remote effects before another mutation. Record reconciliation on the same attempt with `reconciled: true`. A known failed retry names `retry_of` and the corrected cause. Exact event retries only recover receipts and never repeat the operation.
3. Record `targets` with the current checked execution revision and every PR's URL, exact head, base branch and base SHA. Resolve required check names and expected bot reviewer logins from repository policy and the approved Plan. An empty expectation requires confirming that none apply. New pushes or changed dependency context need affected execution checks and new targets. Preserve the whole stack's intended bases and heads.
4. Write `observed` to collect fresh authenticated GitHub observations through `gh`. The helper reads paginated checks, statuses, reviews and threads between two PR identity reads. It returns recovery work for stale targets, repair for failed checks/findings, and wait for pending checks, expected bot reviews or draft state. A bot that reports through a check belongs in `required_checks`. `expected_bots` names reviewers whose review must report on the current head. The caller still establishes applicable policy and judges findings against approved intent.
5. Follow `ship next`, continuing authorized repairs, rechecks and waits. A journal lock protects this task's records. It does not serialize other Git clients or guarantee exactly-once external writes. Preserve actual Git/stack ownership and use expected-head checks or leases where the operation supports them. Reconcile concurrent changes before further writes.
6. Write `ready` only after Iterate is complete at the same revision. It refreshes GitHub again and requires all recorded PRs open and non-draft, exact heads/bases, passing checks, completed expected bot reviews and no effective change requests or unresolved current threads. Current verification and retained review artifacts must still match their captured hashes. Historical logs and receipts remain readable when old artifacts disappear. A `ready` event proves a particular observation, not permanent readiness. `ship next` refreshes a previously ready PR before returning completion.

Retain pending work in Auto's Ship stage. Record the external trigger and actual authorized wait/resumption mechanism. Without one, report how to resume. A timestamp or saved journal does not restart a terminated process. Complete with the PR links, checked heads, evidence and remaining limitations. Do not add a mandatory reviewer-request question.
